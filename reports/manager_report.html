Limits and caveats

  • The data is synthetic. Real fraud is messier; these numbers show the pipeline works, not what a bank would see.
  • Stealth fraud is essentially invisible to these 12 inputs. Catching it needs richer signals (device and network data, customer history).
  • Account takeovers are caught about half the time. The first transaction of an episode looks normal; later ones are easier.
  • The fraud score is a ranking, not a probability. The model trained on a down-sampled set of genuine transactions.
  • Precision depends on how common fraud is. Fraud was rarer in the test period (0.23% of transactions) than in the period used to set the alert threshold (0.38%); with rarer fraud, the same rule produces a larger share of false alerts.
  • Next steps: add device and customer-history signals, retrain on a schedule, and review the alert threshold with the fraud operations team.

Glossary

  • Recall (fraud caught): of all real fraud, the share the model flagged.
  • Precision (alerts that are real): of everything flagged, the share that was real fraud.
  • False alarm: a genuine transaction flagged as fraud, which creates review work and customer friction.
  • Drift (PSI): how far live data has moved from the data the model learned on. Under 0.1 stable, over 0.2 significant.
